# 我们为什么绕了这么多路

最初我们把困难理解成“缺一个更适合经济数据的网络”。于是读论文、改分组、换表示、加入事件结构、尝试新损失和近邻。很多次结果只是小幅变化，或者一个年度提高、另一个年度下降。

后来回头看，走弯路不全是因为模型难，而是我们有时没有先写清楚：这一轮究竟要排除哪种解释。

## 真正需要提前做的事

**先定时间口径。** 违规发生、公告、处理文件、年报披露不是同一时间。按披露年预测和按发生年识别是不同任务。新标签快照下的结果也不能直接与旧快照比。

**先检查键，再解释结果。** 标签完整度分支曾出现特征与标签索引错位；该版本结果作废，修正后重新诊断。代数等价损失的浮点求和路径也曾造成训练差异。它们不是算法受益，不应进入贡献表。

**分开新信息与新结构。** 审计信息确实有增量，但FiLM与普通接入接近。不能把前者当成后者的证明。

**明确比较的是哪个预测器。** 单种子平均与六模型集成是不同的比较对象，logit平均与概率平均也可能交换名单。后来我们固定部署聚合口径，重新核对正式结果。

**不要把碰到门槛边缘当成值得继续调的理由。** 门槛未过、置信区间跨零、没胜随机对照是不同判断。重复试验越多，越应关注选择偏差，而不是继续寻找零点几的好看结果。

## 我们付出的代价

阶段性计划和命名变化过多，旧文档里曾有多个“最终模型”。讨论容易围绕最近一次结果转向，完整数据与机制分析有时被放在后面。AI降低了写代码和组织试验的成本，也让我们更容易在没有充分想清楚时启动下一轮。

问题不是简单地“不要用AI”，而是需要有人对假设、比较口径和停止条件负责。模型能运行不等于实验回答了原问题。

## 留给下一位同学

在训练前写下预期、理由、失败条件和预算。先做能否分辨预期差异的评估，再开大规模训练。保留被推翻的判断，同时明确哪一版已经作废。把数据新增收益、算法结构收益、工程收益分开报告。只有受控模拟中的优势，不能补成真实数据上已经验证的贡献。

这不是一个保证成功的教程。它是一份我们希望自己在项目开始时就能读到的记录。
